# سیاست منابع سرور و اعتماد — راه‌یاب VPN (نسخه بازطراحی v3)

## هدف
راه‌یاب باید سرورهای عمومی را از منابع قابل شناسایی دریافت کند، هر سرور را پیش از نمایش/اتصال ارزیابی کند و سطح اعتماد را صریح نشان دهد. «رایگان» به معنی «امن»، «خصوصی» یا «پایدار» نیست.

## منبع عمومی فعال در کد فعلی
- نام: VPN Gate Public VPN Relay Servers
- متولی: پروژه دانشگاه تسوکوبا، ژاپن
- API مورد استفاده فعلی: https://www.vpngate.net/api/iphone/
- صفحه رسمی: https://www.vpngate.net/en/
- راهنمای رسمی/FAQ: https://www.vpngate.net/en/about_faq.aspx
- نوع سرویس: رله‌های OpenVPN/SoftEther/L2TP/SSTP که توسط داوطلبان مستقل میزبانی می‌شوند.
- ثبت‌نام: لازم نیست؛ نام کاربری و گذرواژه عمومی سرویس برای اتصال OpenVPN در صفحه رسمی اعلام شده است.
- تغییرپذیری: سرورها و IPها ممکن است هر زمان ظاهر/ناپدید یا تغییر کنند.
- حریم خصوصی: سیاست رسمی ضدسوءاستفاده VPN Gate اعلام می‌کند لاگ اتصال در سرورهای تجمیعی حداقل سه ماه نگهداری می‌شود و رله‌های داوطلبانه packet-header logs را حداقل دو هفته نگه می‌دارند. بنابراین این سرویس برای ناشناس‌ماندن یا داده‌های حساس مناسب فرض نمی‌شود.

## منابعی که نباید بدون راستی‌آزمایی وارد شوند
- لینک‌های اشتراک/کانفیگ ناشناس در کانال‌ها و سایت‌های متفرقه
- فایل‌های کانفیگی که از آینه‌های ناشناس دریافت شده‌اند
- هر منبعی که مالک، سیاست ثبت داده، قالب داده یا مجوز استفاده‌اش مشخص نیست

در نسخه فعلی MainActivity، دو آینه GitHub ثالث نیز به‌عنوان fallback وجود دارند. این آینه‌ها رسمیِ دانشگاه تسوکوبا نیستند و صرفاً در صورت در دسترس نبودن منبع اصلی امتحان می‌شوند. نباید به آن‌ها سطح اعتماد رسمی داده شود. منبع رسمی API باید اولویت قطعی داشته باشد. طراحی بعدی باید فهرست آینه‌های رسمی VPN Gate را از صفحه رسمی mirrorها دریافت کند؛ اما نباید صرفاً برای کارکردن آینه‌ها، TLS را خاموش یا HTTP را بی‌قیدوشرط فعال کرد.

## رتبه‌بندی پیشنهادی سرورها
1. صلاحیت پروفایل: parse موفق، remote endpoint معتبر، پورت و پروتکل پشتیبانی‌شده.
2. دسترسی شبکه: TCP connect probe با timeout کوتاه؛ این فقط reachability است و اتصال VPN را ثابت نمی‌کند.
3. اتصال VPN: دریافت رویداد CONNECTED از موتور.
4. عبور واقعی ترافیک: درخواست HTTPS از داخل تونل با socket محافظت‌نشده و تأیید تغییر IP خروجی.
5. پایداری: نمونه‌برداری چندباره از latency، قطع‌و‌وصل و نرخ موفقیت.
6. برچسب حریم خصوصی: «رله داوطلبانه عمومی — اپراتور مستقل؛ برای حساب‌ها و اطلاعات حساس توصیه نمی‌شود».

## قواعد ایمنی و شفافیت
- هیچ سرور عمومی با برچسب «امن»، «بدون لاگ» یا «تضمینی» نمایش داده نشود مگر شواهد مستقل و معتبر وجود داشته باشد.
- پینگ TCP یا سرعت اعلام‌شده توسط منبع، معادل سرعت واقعی تونل نیست.
- نشان سبز فقط پس از تست HTTPS از داخل تونل و تأیید IP خروجی مجاز است.
- در صورت خطا، برنامه باید علت را از رویداد موتور تفکیک کند: resolve، TCP، TLS، authentication، TUN، route، DNS یا traffic probe.
- برای بانکداری، حساب‌های حساس و انتقال داده محرمانه، از رله‌های عمومی داوطلبانه استفاده نشود.
- هیچ کلید خصوصی، رمز، توکن یا کانفیگ کاربر در گزارش تشخیصی ثبت نشود.

## مسیر فنی بازطراحی
- نگه‌داشتن OpenVPN 3 برای سازگاری با پروفایل‌های VPN Gate.
- بررسی ادغام sing-box به‌عنوان موتور چندپروتکلی جداگانه؛ صرف افزودن dependency کافی نیست و باید TUN lifecycle، ABIهای Android، مدیریت فایل پیکربندی، توقف امن و تست ترافیک واقعی پیاده‌سازی شود.
- موتور جدید نباید جایگزین مسیر OpenVPN شود تا وقتی تست‌های build و device pass شوند.
- تست‌های اجباری پیش از انتشار: اتصال واقعی، عبور IPv4/IPv6، DNS leak، قطع اینترنت هنگام افت تونل، reconnect، توقف سرویس، و تست روی Android 16 / Galaxy A15.

## وضعیت فعلی
این سند سیاست و طراحی را ثبت می‌کند. این commit به‌تنهایی موتور جدید، سرور اختصاصی، یا اتصال تأییدشده روی گوشی اضافه نمی‌کند. سرورهای VPN Gate در کد فعلی از API عمومی آن دریافت می‌شوند؛ قابل اتکا بودن هر رله باید در زمان استفاده جداگانه سنجیده شود.
